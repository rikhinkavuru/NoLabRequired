# Chapter 18. Sequence alignment

## Exercise 18.1

**Goal.** Align the human and mouse *BRCA1* coding sequences and say where the
extra bases went.

**Answer.** Three things.

| | |
|---|---|
| Alignment score | 2185.0 |
| Percent identity | 75.05 percent, over the 5,403 columns where both rows carry a base |
| Gap runs | 33 separate runs, the longest 42 columns |

The code, with the four scores the exercise fixes:

```python
from Bio import SeqIO
from Bio.Align import PairwiseAligner

seqs = {}
for record in SeqIO.parse("data/sequences/brca1_cds_five_species.fasta",
                          "fasta"):
    seqs[record.id] = str(record.seq)
human = seqs["human"]
mouse = seqs["mouse"]

aligner = PairwiseAligner(mode="global")
aligner.match_score = 1
aligner.mismatch_score = -1
aligner.open_gap_score = -10
aligner.extend_gap_score = -1

alignment = aligner.align(human, mouse)[0]
human_row = alignment[0]
mouse_row = alignment[1]
print(alignment.score, len(human_row))
```

```
2185.0 5628
```

The identity number depends on which denominator you name, and the exercise asks
you to name it:

- 4,055 identities over the 5,403 columns where both rows have a base: **75.05
  percent**.
- The same 4,055 over all 5,628 columns: **72.05 percent**.

Neither is wrong. Chapter 19 reports 73.18 percent for the same two genes off a
different program aligning five species at once, which is a third number. A
percent identity is a property of an alignment, and there's more than one
alignment.

The gaps, counted as runs rather than columns:

```
human row:  6 runs, 36 gap columns
mouse row: 27 runs, 189 gap columns
           189 - 36 = 153
```

Sorted, the 33 runs are:

```
3 3 3 3 3 3 3 3 3 3 3 3 3 3 3 3 3 3 3 3 3 6 6 6 6 12 12 12 12 12 15 21 42
```

**Every one of the 33 is a whole number of codons.** No run of 1, no run of 2,
no run of 4. The shortest is 3 columns and the longest is 42, which is 14 codons.

And the 153 bases are scattered rather than parked at one end. Counting gap
columns in each third of the alignment gives 24, 111 and 90, which adds to 225,
the 36 human gap columns plus the 189 mouse ones.

**Why the 153 has to hold whatever scoring you pick.** Global mode forces both
sequences end to end into the same number of columns. The human coding sequence
is 5,592 bases and the mouse one is 5,439, so the mouse row must carry 153 more
gap columns than the human row, always. Divide by three and you get 51 codons,
and 1,863 minus 1,812 gives the same 51 from the two protein lengths in Chapter
5. Two records fetched off two different pages, agreeing to the base.

**Why all 33 runs are whole codons.** Nobody told the aligner about codons. An
indel of one or two bases inside a coding sequence moves every codon boundary
downstream of it, so the rest of the protein comes out as unrelated amino acids
and usually hits an early stop. A broken *BRCA1* doesn't get carried down a
lineage. What survives long enough for anybody to sequence it is overwhelmingly
whole codons, and that fell out of the letters.

**The most common wrong answer.** A gap difference that isn't 153. Two causes,
and the check box names both. You're in local mode, which is free to trim the
ends and therefore free to break the invariant. Or you loaded the wrong two
records: the ids in that file are lowercase, so `seqs["Human"]` raises a
`KeyError` and `seqs["chimpanzee"]` quietly aligns the wrong pair. Print
`list(seqs)` to see the five names you have.

The second most common is reporting a percent identity with no denominator named
beside it. 75.05 and 72.05 are the same alignment, and a reader given one number
with no denominator can't tell which you did. The same goes for the four scores:
report a percent identity without reporting the scores you used and you've
reported nothing.

The third is treating `[0]` as decoration. `len(aligner.align(human, mouse))`
tells you how many arrangements tie for the highest score, and here it's over two
quadrillion. Every claim in this exercise is a claim about one member of that
pile, and no output anywhere says otherwise.

## Exercise 18.2

**Goal.** Predict what a cheaper gap does to the answer, write the prediction
down, then run it.

**Answer.** Two directions predicted, two measured values beside them.

| | Prediction | Measured, with `open_gap_score = -2` |
|---|---|---|
| Percent identity | most people predict it falls | **rises**, 75.05 to 77.42 |
| Count of gap runs | most people predict it falls | **rises**, 33 to 122 |

The run:

```python
aligner.open_gap_score = -2
alignment = aligner.align(human, mouse)[0]
human_row = alignment[0]
mouse_row = alignment[1]
print(alignment.score, len(human_row))
```

```
2540.0 5658
```

And the numbers behind the table: 4,160 identities over 5,373 both-base columns
gives 77.42 percent. The human row now carries 41 gap runs across 66 columns and
the mouse row carries 81 runs across 219 columns.

**The 153 invariant still holds.** 219 minus 66 is 153. It has to, and checking
it is how you know you changed the scoring rather than the mode.

**What actually got worse.** The count of whole-codon runs. Under the original
scoring all 33 runs were whole codons. Under the cheaper gap, 30 of the 122 are.
The other 92 are runs of 1 and 2 and 4 and 5, and a one-base indel in a coding
sequence is a frameshift that would have destroyed the protein. So the
better-looking alignment is describing 92 events that biology says didn't happen.

**Why a cheaper gap raises percent identity.** A gap becomes a cheap way to buy a
matching column. At an open price of 10 the program will accept a mismatch
instead, because opening a gap costs more than the mismatch does. Drop the open
price to 2 and it will scatter small gaps wherever they let a matching base line
up. The identity number counts matching columns and doesn't count how many gaps
you bought them with, so the headline goes up while the answer gets worse.
Nothing errors and nothing warns.

**The most common wrong answer.** Predicting that identity falls, and then
writing 75.05 down anyway because the prediction felt right. The chapter's author
made the same prediction and says so: a worse setting should give a worse number.
It gives a better-looking number. That's the whole exercise, and it only pays out
if the prediction is on paper before the run.

The second most common is changing `extend_gap_score` as well, or instead. The
exercise changes one number and leaves everything else alone, and the point is
that one number moved the identity by 2.4 points and the event count by a factor
of nearly four.
