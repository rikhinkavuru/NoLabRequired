# Chapter 30. Resources, honestly annotated

## Exercise 30.1

**Goal.** Annotate one resource this chapter left out, and commit to the fourth
field before opening the thing.

**The resource is yours to pick**, so here's one worked example. The chapter never
lists the documentation for matplotlib, and every figure in Part 4 came out of it.

**Five lines, in the order the exercise asks for them.**

1. *My guess at the bad part, written first.* It'll assume I already know which
   plot I want.

2. *What it is.* The reference and example gallery for the plotting library that
   drew every figure in Chapters 21, 24 and 25. Function-by-function
   documentation, plus a gallery of finished pictures with the code under each
   one.

3. *When I'd take it.* When I know what picture I want and need the name of the
   function that draws it, or when a keyword argument didn't do what I expected.

4. *What it costs.* Nothing, and no account.

5. *What it turned out to be bad at, written after going one level in.* The
   gallery is organized by what a picture looks like rather than by what question
   a figure answers. So you find `scatter` in seconds, and you never find out that
   a volcano plot is a scatter with two thresholds drawn on it. The examples also
   build their data inline, a few arrays made up on the spot, so nothing there
   shows you how a column of a DataFrame becomes an axis. Both of those are the
   gap Chapter 21 exists to fill.

**The check.** Compare line 1 with line 5. Line 1 was a guess about the reader's
starting point. Line 5 names two specific things about how the material is
organized, and neither of them is visible from the front page. That's what going
one level in buys you.

**Why the fourth field is the one that matters.** Every resource page in this
field prints what a thing is, when you'd take it, and what it costs. None prints
where its own material stops working, because nobody advertises that. A resource
doesn't fail in general. It fails you, at the point where what it assumes about
you and what's true about you come apart. The Software Carpentry shell lesson is
excellent and its bad part is that lesson one has you install a shell, which is
the exact wall Chapter 1's reader already hit once.

**The most common wrong answer.** A first line and a last line that say the same
thing. That means the bad part was visible from the front page and you never went
inside. Go one level in, meaning open an actual lesson or an actual reference page
and try to do one real thing with it, then write line 5 again. The gap between a
guess and a finding is the whole exercise.

The second most common is a fifth line that reads as a complaint about the
subject rather than about the resource. "Statistics is hard" isn't an annotation
of StatQuest. "A video holds no data and no code, so you can watch ten and still
not have run one" is, because it names something about the format that a reader
can act on by pairing it with something else.

The third is picking a resource the chapter already covers. Rosalind, Galaxy,
Software Carpentry, Happy Belly, the Biopython Tutorial, EMBL-EBI training,
Bioconductor, Chatomics, Biostars, Bioinformatics Stack Exchange, Automate the
Boring Stuff and StatQuest are all annotated in the chapter. The exercise asks for
one it left out, and the point is to practice writing the fourth field for
something nobody wrote it for.
