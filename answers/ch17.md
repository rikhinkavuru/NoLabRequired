**Goal.** Redo Exercise 15.1 with `SeqIO` in about three lines, then say what the

**Answer.** Three lines:

```python
from Bio import SeqIO

for record in SeqIO.parse("data/sequences/messy.fasta", "fasta"):
    print(record.id, len(str(record.seq).rstrip("*")))
```

**The three sentences.**

1. *Which defects the library absorbed.* Three of the four, with no code from
   you. It glued the 60-column wrapping back together and read the record written
   on one unbroken line, so mixed wrapping inside one file cost nothing. It read
   straight past the blank line sitting inside the mouse record instead of ending
   the record there. And it cut every identifier at the first space, so
   `record.id` is `NM_007294.4` rather than the whole header.
2. *Which one it handed back.* The trailing `*` on the fourth record, which is
   why that length comes back 181 and not 180.
3. *Why handing it back was the right call.* In a protein FASTA file `*` is a
   legal character. It marks the stop codon, and your own `translate` from
   Chapter 14 put one at the end of the protein it handed you. Nothing tells
   `SeqIO` whether this file holds DNA or protein and it doesn't guess, so a
   parser that quietly deleted `*` would corrupt every protein file it ever
   touched. What it means in your file is your decision, and the library declined
   to make it for you.

**The last part: what if the underscore were a space?** The fourth header would
be `>NM_007294.4 translated leftover stop character`, and `record.id` cuts at the
first space, so both records would come back with the id `NM_007294.4`. A
dictionary you build yourself in a loop would let the fourth record land silently
on top of the first, and you'd hold three records where you counted four.
Biopython has a shortcut that refuses instead:

```python
SeqIO.to_dict(SeqIO.parse("data/sequences/messy.fasta", "fasta"))
```

```
ValueError: Duplicate key 'NM_007294.4'
```

The fix is to key on `record.description`, which is everything after the `>` and
cut at nothing, or to repair the headers in the file.
