# Chapter 26. Writing it up and sharing it

## Exercise 26.1

**Goal.** Publish the project so a stranger can open it, and keep the link.

**The address is yours**, so what follows is the worked example of everything
around it: the four conditions, the README, and the one number the check asks
you to verify.

### The artifact

One public repository holding two files:

```
analysis.ipynb     the Chapter 24 notebook, outputs kept
README.md          at the top level, not inside a folder
```

Plus `GSE60450_counts.tsv.gz` beside them, because at 513,592 bytes it's small
enough to sit in the repository and a reader then needs nothing else.

### The four conditions

1. The repository is public.
2. The notebook is in it, under a name ending `.ipynb`.
3. `README.md` sits at the top level, so GitHub prints it on the front page.
4. Every file the notebook opens is either in the repository or fetched by the
   notebook from a public address.

### The README

```
# Brca1 across mouse mammary development

## Question
Does Brca1 expression change between virgin and lactating mice, and
does the answer depend on which cell type you look in?

## Data
GSE60450: 12 RNA-seq samples of mouse mammary gland, basal and luminal
cells, from virgin, pregnant and lactating animals.
Counts file: 513,592 bytes, 27,179 rows keyed by Entrez gene ID.
Downloaded from GEO. I did not generate this data.

## How to run it
1. Open analysis.ipynb in Google Colab.
2. Restart the runtime and run every cell from the top.
3. Nothing is installed, and no account is needed beyond a Google one.

## What I found
In basal cells, mean Brca1 falls from 8.3 CPM in virgin animals to
0.9 CPM in lactating ones. Dividing one mean by the other gives 9.2.
The test in the notebook runs on logged counts and reports a log2
fold change of -2.29 with an adjusted p-value of 0.0693, above the
0.05 threshold I fixed before looking. Only 9 genes in that
comparison clear 0.05 at all. In luminal cells Brca1 hardly moves.

## What this does not establish
Two samples per group. Brca1 tops out at 494 raw reads in its best
sample, low enough that counting noise alone moves the ratio. The data
was collected by Fu and colleagues to study a different gene, Mcl1
(PubMed 25730472). Nothing here shows that lactation causes the change.
```

### The number check

The check says the fold change in your README has to be the two group means
in your notebook, divided one by the other.

```
8.3 / 0.9 = 9.2
```

Divide the means before they were rounded and you get 9.4 instead. Both are fine
and neither is the log2 fold change of -2.29, which comes back as 4.9 when you
turn it into a ratio. Three numbers describe one change, and the README prints the
two group means beside the ratio so a reader can redo the division in ten seconds.
A README that prints `9.2` and nothing else hands a reader no way in.

### The test that decides whether any of this happened

Open the address in a private browsing window, signed in to nothing. You should
see the README text on the front page and the notebook listed underneath by name.
Open the notebook: its code and its saved outputs should render as a page, with no
runtime and no sign-in anywhere.

**The most common wrong answer.** A private repository. This is the failure that
hides itself from the only person in a position to notice it, because your
repository looks identical from your chair whether the world can reach it or not.
You're signed in to the account that owns it. Everybody you send the link to gets
a 404 and quietly decides the link is broken. The private window is the only test
that works, and it takes ten seconds.

The second most common is publishing before running restart and run all. A
notebook has two histories: the code on the page, which is what a reader gets, and
the order you really ran things in, which nobody can see. Edit a cell and don't
re-run it, and the output underneath stays where it was, left over from a previous
version of the code. On screen the two look like a pair, and they'll look like a
pair on a web page. Run restart and run all, then publish, in that order and in the
same sitting. Then find the *Brca1* line: its log2 fold change should still read
-2.29 and its adjusted p-value 0.0693.

The third is a README that quotes the ratio and the log2 fold change as though one
were the other. They disagree, 9.2 against 4.9, and both are right. Print the
method beside the number.

The fourth is the file name. Colab calls a new notebook `Untitled0.ipynb`, and a
copy of somebody else's keeps the original name with `Copy of` on the front.
Either will follow you into the repository. The name in your README and the name
in the folder have to be the same string, character for character. That's Chapter
5's accession rule applied to your own files.
