# Chapter 15. Files and formats

## Exercise 15.1

**Goal.** Write a FASTA parser for `data/sequences/messy.fasta` with no library
at all, and print what's in the file.

**Answer.** Four lines, in file order:

```
NM_007294.4 480
NM_001045493.1 420
NM_009764.3 480
NM_007294.4_translated 180
```

The parser:

```python
records = []
identifier = None
pieces = []

for line in open("data/sequences/messy.fasta"):
    line = line.strip()
    if not line:
        continue
    if line.startswith(">"):
        if identifier is not None:
            records.append((identifier, "".join(pieces)))
        identifier = line[1:].split()[0]
        pieces = []
    else:
        pieces.append(line)

if identifier is not None:
    records.append((identifier, "".join(pieces)))

for identifier, sequence in records:
    print(identifier, len(sequence.replace("*", "")))
```

Five decisions in there, one per defect:

| Line | What it handles |
|---|---|
| `line.strip()` | trailing newlines, and it makes the blank-line test work |
| `if not line: continue` | the blank line sitting inside the third record |
| `line[1:].split()[0]` | the spaces in every header |
| `"".join(pieces)` | mixed wrapping, 60 columns in one record and no break in another |
| `.replace("*", "")` | the `*` the last record's tool left behind |

The `if identifier is not None` block after the loop is the fifth thing, and
it's the one people leave out. A FASTA record ends when the next `>` arrives or
when the file does, and the loop only ever sees the first of those.

**The last part of the exercise: what should a parser do if that underscore were
a space?** It should refuse. `NM_007294.4` and `NM_007294.4_translated` stay
apart only because of one underscore. Put a space there and both records answer
to `NM_007294.4` once you cut at the first space, and a dictionary keyed on the
identifier silently drops one of them. You'd count four records in the file and
hold three.

So: keep the full description alongside the cut identifier, and raise on a
duplicate identifier rather than overwriting. Chapter 17 shows Biopython doing
exactly that. `SeqIO.to_dict` refuses to build the dictionary at all and says
`ValueError: Duplicate key 'NM_007294.4'`, where a loop you write yourself
refuses nothing.

**Why the lengths are what they are.** The file's records are 480, 420, 480 and
181 characters of sequence. The fourth is 180 bases and one `*`, and the exercise
says not to count the `*` as a base, so 180 is the answer. Nothing in the FASTA
format says whether the file holds DNA or protein, which is why the `*` is a
decision you make rather than one the format makes for you.

**The most common wrong answers.** All four are in the check, and each one
has a single cause:

- **240 for the third record.** You stopped reading at the blank line, treating
  it as a record boundary. It isn't. Only a `>` ends a record.
- **181 for the fourth.** You counted the `*`.
- **60 or 61 for three of the four.** You're keeping the last line of each record
  instead of joining them, usually from `sequence = line` where
  `pieces.append(line)` belongs. Record 2 looks right, at 420, because its whole
  sequence sits on one unbroken line, so three of your four lengths are wrong and
  one is accidentally fine.
- **Fewer than four lines.** Your loop is overwriting a record, or the final
  record never got appended because the append only happens when a new `>`
  arrives.

There's a fifth worth naming because nothing in the check catches it. Taking the
identifier as `line[1:]` with no split gives you the entire header, spaces and
all, so record 1 comes out as `NM_007294.4 Homo sapiens BRCA1 mRNA, wrapped`.
Every length is right and every identifier is wrong, in the direction that makes
the collision above invisible.
