**Answer.** The function, with a docstring saying what it assumes, and three

```python
def translate(dna):
    """Translate a DNA string into one-letter amino acids.

    dna must be upper case, must contain only A, C, G and T, and its
    length must be a multiple of three. Reading starts at the first
    base given, so the reading frame and the strand are the caller's
    problem. Stop codons come back as *.
    """
    translated = ""
    for i in range(0, len(dna), 3):
        translated += codon_table[dna[i:i + 3]]
    return translated


for name, sequence in (("coding", coding),
                       ("coding[:30]", coding[:30]),
                       ("other_strand", other_strand)):
    result = translate(sequence)
    print(f"{name:13} {len(result):5} {result.count('*'):4} {result[:10]}")
```

**Why the docstring is three assumptions and not a description.** Nothing in the
body enforces any of them. The code will translate a 42-base slice taken one base
late and hand you 14 perfectly ordinary residues, with no stop codon in them and
no run of repeats. The output can't betray a reading-frame error, so the
docstring is the only place the assumption gets recorded. `help(translate)`
prints it, which is how you'll read it in six months when the question is whether
you can trust a number this function produced.

**Why the rewrite is worth doing at all.** Chapter 13 had you write the same
three lines twice, with four names retyped between the copies. The failure mode
is not that the copy is slow. It's that `other_strand` never makes it into the
second copy, `coding` reads correctly wherever your eye lands, and the notebook
prints a claim that both strands of *BRCA1* start with the same twenty residues.
A parameter fixes it structurally: the body has never heard of `coding`, so
there's no stale name left to forget.

**The most common wrong answer.** A function whose last line is
`print(translated)` rather than `return translated`. It runs, it shows you the
protein, and it hands back `None`. The error arrives one line later and names the
wrong thing:

```
TypeError: object of type 'NoneType' has no len()
```

Python is talking about the value your function handed back, not about your
sequence. Look at the last line of the body.

The second most common is a function that still mentions `coding` inside its
body, so all three calls print the same result. All three lines then read
`1864 1 MDLSALRVEE`, which is a correct answer printed three times to a question
asked once. The `other_strand` line is the one that catches it, because that
sequence has 93 stops in it and 1 is not 93.

The third is calling `translate()` with empty brackets:

```
TypeError: translate() missing 1 required positional argument: 'dna'
```

The definition says the function needs one value and Python will not guess which
sequence you had in mind.
