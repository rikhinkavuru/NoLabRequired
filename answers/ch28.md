# Chapter 28. Getting in without credentials

## Exercise 28.1

**Goal.** Write an issue for a real gap you hit in this book, in a form a
stranger can act on.

**Answer.** Four labeled parts, under 200 words, with the actual output pasted
rather than described. Here's one worked example, and the gap in it is real:
Biopython's message for an unrecognized aligner mode is missing its closing
bracket. Chapter 18's If-it-breaks box quotes it exactly, unbalanced bracket
included.

```
Version:  Biopython 1.87 (printed by Bio.__version__), Python 3.14,
          Google Colab

Steps:    from Bio.Align import PairwiseAligner
          PairwiseAligner(mode="semiglobal")

Expected: an error naming the modes the constructor accepts, with the
          list closed.

Actual:   ValueError: invalid mode (expected 'global', 'local', or 'fogsaa'
```

That's 47 words in the four fields. The steps are two lines, anybody can paste
them, and the last line of what comes back is the same last line I got.

**Why each field is there.**

- *Version* is the field that isn't in Chapter 16's four. A forum question is
  about your code and an issue is a claim about somebody else's, so the
  maintainer needs to know which build you were on. `Bio.__version__` prints it.
- *Steps* is Chapter 16's minimal reproducible example. Cut until deleting one
  more line makes the problem go away. Every line you delete is a line you've
  ruled out, which is the same work as finding the bug.
- *Expected* is Chapter 16's "what you were trying to get", in one sentence.
- *Actual* is pasted. Not tidied, not summarized, not retyped from memory. A
  maintainer searches their own code for the string you paste, and a paraphrase
  matches nothing.

**The check the exercise asks for.** Start a fresh Colab runtime and follow your
own steps exactly as written, adding nothing. The problem should happen again. If
it doesn't, what you have isn't a reproduction yet, and the missing piece is
usually a step you'd done so often you stopped seeing it. For the example above,
the missing step is almost always `!pip install biopython`, which every session
needs and which nobody thinks of as a step.

**The most common wrong answer.** A screenshot. Nobody can search a picture, and
the person reading your issue wants to paste your message into the same box you
did. This is the single commonest failure and it's free to avoid.

The second most common is an issue about your own code. A gap you hit because you
misread a page is a question for Biostars, and a gap where the software behaves
differently from what its own documentation says is an issue. The test is whether
a stranger could fix it in their repository. Nobody can fix your typo.

The third is describing the error instead of pasting it. "It complains about the
mode" is true and unsearchable.

The fourth, and this one costs nothing to accept: filing an issue and getting no
reply. Plenty of issues get none. That isn't a verdict on you, and it isn't
information either.

## Exercise 28.2

**Goal.** Draft the message about your Chapter 26 project, addressed to the
person whose figure you reproduced.

**Answer.** One message, under 150 words, carrying five things. This is a worked
example built on the GSE60450 project, with the surname left as a placeholder
because the message is yours to address.

```
Subject: reproduced Figure 2 of Fu et al. 2015 from GSE60450

Dear Dr <surname>,

I reproduced Figure 2 of your 2015 Nature Cell Biology paper from
GSE60450. The notebook runs top to bottom from a clean start:
<link>.

My version separates the basal and luminal samples in the same order
yours does. The one thing I could not work out from the methods is
whether the low-count filter ran before or after the library-size
normalization.

I am not asking for a position or for your time beyond a sentence. If
there is a short answer I would be glad to have it, and if there is
not, no reply is needed.

<your name>
<link to the rest of your work>
```

That's 118 words in the body. The figure number carries over from Chapter 28's
own template and is a placeholder: put in the panel you actually rebuilt in
Exercise 27.1.

**The five things, pointed at.**

| | Where |
|---|---|
| What you did | first sentence, and again in the subject line |
| A link | second sentence, in the opening paragraph |
| One question | third paragraph, one sentence, answerable in one line |
| What you aren't asking for | fourth paragraph |
| Your name | the signature |

**Why the question is the shape it is.** "Did the low-count filter run before or
after normalization?" can be answered while somebody is standing up. It has two
possible answers and the person who wrote the methods knows which one without
looking anything up. Compare it with "Do you have any advice?", which can't be
answered at all, which is why it isn't.

**The check the exercise asks for.** Work out the shortest honest answer to your
question. If it runs past two sentences, the question is too big and a busy person
won't start it. The example above answers in four words.

**The most common wrong answer.** A link you never opened signed out. Click the
link in your own message and it opens, because you're signed in to the account
that owns it. A private repository and a Drive file set to restricted both look
exactly like public ones to their owner. The person you wrote to gets a sign-in
wall or a 404, decides the link is broken, and doesn't reply to tell you so. Paste
your link into a logged-out window before you send anything.

The second most common is leading with your background. "I am a biology graduate
with an interest in computational methods" is a claim, and a stranger has no way
to check a claim. The link in the first paragraph is the only part of the message
they can verify without taking your word for anything, which is why it goes at the
top rather than at the bottom.

The third is cutting the line that says what you aren't asking for. It reads like
filler and it's what makes the message cheap to answer. A message that might be
building toward a request for a position costs the reader a decision before they
can reply. This one costs a sentence, or nothing.

The fourth is a subject line reading `Inquiry regarding research opportunities`.
It tells the reader nothing about whether the next thirty seconds are worth
spending.

**On the outcome.** Most of these produce nothing, and treating silence as the
ordinary result is the only sustainable way to send them. You can't tell a message
that was read and declined from one that was never opened, and neither can anybody
else. Send them on a schedule, one a week, to people whose papers you were reading
anyway. Sending is your call. The artifact this exercise wants is the message.
